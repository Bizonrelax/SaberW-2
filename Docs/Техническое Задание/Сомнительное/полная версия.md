## 2. Архитектурные принципы

1. **Никаких классов-богов.** Каждый класс — одна ответственность. Модель, сериализация, сжатие, UI — разделены.
2. **Тексты — в ресурсах.** Все надписи, названия окон, тексты справки, ошибки хранятся в отдельных ресурсных файлах (`messages.properties`, `help.html` и т. п.) или классах-константах. Классы логики не содержат «зашитых» строк интерфейса.
3. **Никаких «магических» чисел.** Все параметры — в конфигурации или константах с именами.
4. **Сериализация отделена от модели.** Классы модели — простые POJO. Логика чтения/записи JSON — в отдельном слое.
5. **Ядро сжатия не знает про GUI.** Ядро принимает текст и параметры, возвращает результат и словарь. GUI вызывает ядро.
6. **Всё тестируемо.** У ядра есть unit-тесты, не требующие GUI.
7. **Инвариант экранирования.** После подготовки текста к сжатию все литеральные `§` и литеральные CJK из диапазона кодов (U+3400–U+4DBF) представлены экранированными последовательностями (`§§`, `§#<CJK>`). Это гарантирует однозначность лево-правого парсера.

## 3. Термины

- **MVP** — минимально работающая версия.
- **Round-trip** — проверка «сжать → распаковать → исходный текст».
- **tiktoken** — библиотека OpenAI для подсчёта токенов. Внешняя зависимость, вне MVP.
- **Агрессивное сжатие** — режим с пониженными порогами (см. таблицу в разделе 9.2). Не меняет `minWordLength`; меняет только пороги и минимальную длину фразы.
- **Нормализация регистра** — приведение к нижнему регистру. Необратимо. При включённой нормализации round-trip побуквенно не гарантируется (см. раздел 23).
- **Кандидат** — единица (слово или фраза), которую рассматриваем для кодирования.
- **Код** — последовательность символов, заменяющая кандидата.
- **Код ступени 1** — односимвольный код (один CJK-символ из Extension A).
- **Код ступени 2 (префиксный)** — трёхсимвольный код вида `§XY`, где `X`, `Y` — CJK-символы, `§` — префикс.
- **Метаданные словаря** — служебная информация о словаре.
- **ИД** — идентификатор словаря, 6 символов.
- **Многоуровневое сжатие** — итеративное сжатие, где код верхнего уровня ссылается на последовательность кодов нижнего уровня.
- **Поглощение словаря** — работа по уже готовому словарю без создания нового.
- **Цикл сессии** — последовательность: сжатие → отправка боту → ответ бота → распаковка → дополнение словаря → новое сообщение.
- **Класс-бог** — класс с чрезмерной ответственностью. Запрещён.
- **Новая запись** — запись словаря с `sentToBot == false`, то есть ещё не отправленная боту.
- **Применение** — факт использования кода при сжатии (`codeAppliedCount`). Распаковка учитывается отдельно (`decompressCount`).
- **Экранирование CJK** — замена литерального CJK-символа из диапазона U+3400–U+4DBF на `§#<символ>` при подготовке текста к сжатию.
- **Атомарная единица экранирования** — `§§` (литеральный `§`) или `§#<CJK>` (литеральный CJK). При токенизации такая последовательность образует **один токен-разделитель** и не разбивается на части.
- **Атомарная единица декомпрессии** — одна из последовательностей, распознаваемых лево-правым парсером: `§§`, `§#<CJK>`, `§<CJK><CJK>`, одиночный CJK из U+3400–U+4DBF. Внутри атомарной единицы повторный разбор не производится.
- **Экранированный текст** — результат применения 9.1.1 к исходному тексту. Хранится в словаре в виде текстовых токенов.
- **Рабочая папка** — папка для хранения словарей (`<root>/dicts/`) вместе с резервной (`<root>/dicts-backup/`), определённая `PathResolver` (см. раздел 16). Уникальность ИД проверяется в пределах обеих папок.
- **Уровень записи** — целое число `≥ 1`. Слова имеют уровень 1. Фразы имеют уровень 1 (если не содержат токенов-кодов) или уровень `N+1`, где `N` — максимальный уровень кода в значении (если содержит). Записи уровня 1 могут ссылаться только на слова (см. раздел 19).

## 4. Рабочий цикл

1. Пользователь вводит текст или прикрепляет файл. Словарь либо ещё не загружен, либо уже загружен (продолжение сессии).
2. Программа сжимает текст, показывает результат и словарь. Пользователь копирует через буфер в чат.
3. Нейросеть отвечает сжатым текстом.
4. Пользователь копирует ответ бота и вставляет в SaberW 2.
5. Программа распаковывает ответ, показывает человекочитаемый текст. Даёт выбор: экспорт, копировать в буфер.
6. Пользователь готовит следующее сообщение.
7. Программа ищет новые повторы, отсутствующие в словаре. Дополняет словарь. Сжимает с учётом дополнений. Формирует для бота: только новые строки словаря + обновлённый сжатый текст (см. раздел 18.2).
8. Из словаря нельзя удалять применённые записи. Только неприменённые могут быть удалены (см. раздел 10.7).

## 5. Идентификатор словаря

- Длина 6 символов.
- Алфавит: `A–Z`, `a–z`, `0–9` и дополнительные символы, безопасные для имён файлов во всех поддерживаемых ОС: `! @ # $ % & ( ) = + [ ] { } ^ ; ,`. Итого **79 символов**.
- Символы, запрещённые в именах файлов Windows (`\ / : * ? " < > |`), а также `.`, пробел, `-`, `_` в алфавит **не входят**. `-` и `_` исключены, потому что используются как разделители в именах файлов сообщений (см. 14.6), и их наличие в ИД ломало бы парсинг даты.
- Символ `§` в алфавит не входит (зарезервирован как префикс кодов и экранирования).
- ИД не должен пересекаться с часто встречающимся текстом. **Проверка:** генерируется кандидат; если он встречается как подстрока в исходном тексте текущей сессии, в подготовленном (экранированном) тексте, в сжатом тексте текущей сессии, в тексте инструкции для бота или в значениях записей активного словаря — кандидат отбрасывается.
- Проверка уникальности выполняется **регистронезависимо** в пределах рабочей папки (учёт поведения файловых систем Windows/macOS). При проверке сканируются имена всех `.json` и `.saberw.json` файлов в `<root>/dicts/` и `<root>/dicts-backup/`; для каждого файла ИД извлекается из JSON-поля `id`. **Если файл невалиден, не читается или не содержит поля `id` — файл пропускается, в лог пишется предупреждение (WARN).** Совпадение с хотя бы одним валидным ИД — коллизия.
- Генерация случайная.
- Отображается в интерфейсе.
- Входит в экспорт словаря.
- Количество возможных ИД: `79^6 ≈ 2.43 × 10^11`.

## 6. Метаданные словаря

Хранятся вместе со словарём в одном JSON-файле (см. раздел 17.1). Флаг `transferMetadataOnExport` в настройках приложения определяет, включается ли отдельный `metadata.json` в архив `.saberwz` (см. 10.10). На экспорт «Для бота» флаг не влияет: в сообщение для бота метаданные не включаются никогда.

1. Заметка (произвольный текст пользователя).
2. Ссылки на чаты (URL).
3. Даты применения (список дат в формате `YYYY-MM-DD`, без повторов).
4. `totalCompressions` — количество сжатий.
5. `totalDecompressions` — количество распаковок.
6. `supplementCount` — количество дополнений.
7. `mergeCount` — количество объединений.
8. `exportCount` — количество экспортов (JSON, текстовых, копирований словаря в буфер обмена и экспортов `.saberwz`).
9. `lastExportIncludedMetadata` — были ли включены метаданные при последнем экспорте. Обновляется при экспорте JSON и при экспорте `.saberwz` (в последнем случае — по фактическому значению `transferMetadataOnExport`). Для `.saberwz`, если `transferMetadataOnExport == false`, значение сбрасывается в `false`. **При копировании со словарём (11.1) и при копировании словаря (11.1) не обновляется.**
10. `sizeBytes` — **оценка** размера JSON-файла словаря в байтах. **Алгоритм:** сериализовать корневой объект с `metadata.sizeBytes = 0`; измерить длину полученной строки в байтах (UTF-8); записать это значение в `sizeBytes`. Значение не пересчитывается рекурсивно; при следующем сохранении процедура повторяется. Фактический размер файла может отличаться на число цифр, добавленных при записи значения.
11. `entriesCount` — количество записей (обновляется при сохранении).
12. `totalValueChars` — общее количество символов в текстовых токенах значений (обновляется при сохранении). При подсчёте длины текстового токена экранированные последовательности `§§` и `§#<CJK>` считаются как 2 и 3 символа соответственно (т. е. по длине хранимой строки).

Дата и время создания хранится на верхнем уровне JSON в поле `createdAt` (см. раздел 17.1). В `metadata` не дублируется.

ИД хранится на верхнем уровне JSON.

**`updatedAt`** (в объекте `dictionary`, см. 17.1) обновляется при каждом успешном сохранении словаря в файл.

## 7. Критерий эффективности

Обозначения:
- `L` — длина фразы/слова в **символах** (сумма длин **всех** токенов значения: для текстового токена — длина хранимой экранированной строки; для токена-кода — длина его кода, `1` или `3`). Для уровня 1 (слова) — просто длина строки в экранированном тексте.
- `F` — частота (сколько раз встречается на текущем уровне).
- `C` — длина кода в символах.

Стоимость без сжатия: `F × L`.
Стоимость со сжатием: `F × C + C + L`.
Экономия: `S = (F − 1) × L − F × C − C`.

Формулы для конкретных `C`:
- `C = 1` (код ступени 1): `S = (F − 1) × L − F − 1`.
- `C = 3` (код ступени 2, `§XY`): `S = (F − 1) × L − 3F − 3`.

Правило: кодировать, если `S ≥ порог`. **Порог по умолчанию — `0`.**

Порог `0` означает: записывать всё, что не убыточно прямо сейчас (`S = 0` — нейтрально по текущей выгоде, но даёт будущую выгоду за счёт уже готовой записи словаря). В настройках порог можно поднять до 3, 5, 10.

**Приоритет порога.** Если включён агрессивный режим, порог принудительно равен `−2` независимо от значения `thresholdS`. Если агрессивный режим выключен, используется значение `thresholdS` из настроек (по умолчанию `0`). При выключении агрессивного режима восстанавливается ранее установленное значение `thresholdS`.

Критерий применяется на каждом уровне многоуровневого сжатия. На уровне 1 `L` считается в символах исходного (после экранирования) текста. На уровне `N > 1` `L` считается как сумма длин **всех** токенов значения (текстовых и кодовых; код входит как 1 или 3 символа своего кода).

## 8. Многоуровневое сжатие

1. Программа ищет крупнейшие повторы (до целого текста включительно).
2. Кодирует их.
3. В остатке ищет следующие повторы.
4. Повторяет, пока есть кандидаты с `S ≥ порог`.
5. Каждый код может ссылаться на последовательность кодов любого более низкого уровня (см. раздел 19).
6. Длина фразы по умолчанию не ограничена. Максимум задаётся опционально (защита от бесконечных поисков); по умолчанию `-1` (без ограничения). Если `maxPhraseTokens ≤ 0` — ограничение не применяется, но поиск ведётся до практического предела: пока длина непрерывной последовательности не превышает половину длины текста на текущем уровне. Это защита от комбинаторного взрыва.

### 8.1. Токенизация при многоуровневом сжатии

**Важно:** токенизация выполняется **один раз** на входе, до вставки кодов. После этого текст представляется последовательностью токенов. Коды, вставленные на уровне `N`, становятся **атомарными токенами** и не разбиваются при последующих уровнях. Разбиение на слова и разделители (9.1) применяется только к исходным текстовым токенам.

Токен кода на уровне `N+1` имеет ту же длину в символах, что и его код (`1` для ступени 1, `3` для ступени 2). При подсчёте `L` на уровне `N+1` длина токена-кода учитывается именно так.

### 8.2. Алгоритм поиска повторов

Поиск повторов выполняется на последовательности целочисленных идентификаторов токенов (ID токенов), а не на строках. Это позволяет применять эффективные строковые алгоритмы.

1. **Построение ID-последовательности.** Каждому уникальному токену текущего уровня присваивается целочисленный ID. Текстовые токены различаются по своему строковому содержимому; токены-коды — по своему коду.

2. **Суффиксный массив и LCP-массив.** Для ID-последовательности строится суффиксный массив (например, алгоритмом SA-IS или удвоением) и массив LCP (longest common prefix) длин. Сложность построения — `O(n)` или `O(n log n)`.

3. **Кандидаты.** По суффиксному массиву и LCP-массиву выделяются группы суффиксов с общим префиксом длиной не менее `minPhraseLength` (в токенах). Для каждой такой группы:
   - длина общего префикса `len` ограничивается сверху: `maxPhraseTokens`, если `maxPhraseTokens > 0`, иначе `floor(n / 2)`;
   - для каждого `l` от `minPhraseLength` до `len` подсчитывается количество суффиксов в группе, у которых префикс длиной `l` общий — это частота `F` для фразы длиной `l` с данным содержимым;
   - для каждой уникальной фразы вычисляется `S` и отбрасываются убыточные.

   **В MVP используется полный перебор `l`** с ограничением `maxPhraseTokens` (см. п. 6). Эвристика «локальных максимумов» — вне MVP (раздел 25).

4. **Сортировка.** Кандидаты сортируются по убыванию `S`, при равенстве — по убыванию `L`, при равенстве — по убыванию `F`, при равенстве — по возрастанию лексикографического представления последовательности токенов (детерминированный тай-брейк).

5. **Замена.** Для каждого кандидата проверяется `S ≥ порог` и отсутствие перекрытия с уже закодированными на этом уровне фрагментами. Первый подходящий кандидат кодируется: **все его непересекающиеся вхождения** на текущем уровне заменяются кодом. **Оптимальность набора не гарантируется: замена жадная.** Частоты оставшихся кандидатов пересчитываются (суффиксный массив перестраивается или обновляется инкрементально). Затем поиск продолжается на том же уровне с шага 2.

6. **Практический предел.** При `maxPhraseTokens ≤ 0` для текстов длиной более 1 МБ токенов полный перебор `l` в группе может быть дорогим. В MVP допускается ограничить перебор `l` сверху значением `floor(n / 2)`.

7. **Исчерпание кандидатов на уровне** — ситуация, когда ни один оставшийся кандидат не удовлетворяет `S ≥ порог` или все оставшиеся перекрываются с уже закодированными. Тогда — переход на следующий уровень.

8. **Записи уровня `N`** могут ссылаться только на коды уровня `≤ N−1`, **кроме записей-слов (уровень 1), которые могут быть указаны в значении любой записи-фразы любого уровня** (см. раздел 19).

Это позволяет находить и кодировать целые повторяющиеся структуры — например, весь роман, вставленный трижды.

### 8.3. Кодирование одиночных слов

Одиночные слова (длина 1 токен) не попадают в поиск 8.2, так как `minPhraseLength ≥ 5`. Для них выполняется отдельный проход:

1. Подсчитываются частоты всех слов, удовлетворяющих `L ≥ minWordLength` и не являющихся стоп-словами (стоп-слова не определяются в MVP; все слова допускаются).
2. Для каждого слова вычисляется `S` по формуле для `C = 1` (ступень 1) или `C = 3` (ступень 2, если ступень 1 исчерпана).
3. Слова сортируются тем же тай-брейком, что и фразы.
4. Замена выполняется по тем же правилам, что и для фраз.
5. Слова получают **уровень 1**. Фразы, не содержащие токенов-кодов, получают **уровень 1**. Фразы, содержащие токены-коды, получают уровень `N+1`, где `N` — максимальный уровень кода в значении (см. раздел 19).

Порядок фиксирован: **сначала слова уровня 1, затем фразы уровня 1**, затем переход на уровень 2 (фразы, ссылающиеся на коды уровня 1 и выше). Это гарантирует, что фразы могут ссылаться на коды слов.

## 9. Ядро сжатия

### 9.1. Токенизация и экранирование

**Порядок операций:**

1. **Экранирование — один лево-правый проход по исходному тексту.** На каждом шаге:
   - если текущий символ `§` — вывести `§§` и перейти к следующему символу;
   - если текущий символ — CJK из U+3400–U+4DBF — вывести `§#<символ>` и перейти к следующему символу;
   - иначе — вывести символ как есть.
   Выведенное на этом шаге повторно не обрабатывается.

2. **Токенизация экранированного текста.** Токенизация ведётся по «жадному» правилу, слева направо, со следующими приоритетами:
   3. **Атомарные единицы экранирования.** Если на текущей позиции стоит `§§` — это один токен-разделитель (2 символа). Если стоит `§#<CJK>` — это один токен-разделитель (3 символа). Внутренние символы такого токена не рассматриваются как отдельные токены. Это ключевое правило: без него литеральные CJK и `§` могут быть разорваны при замене.
   4. **Слово** — максимальная последовательность символов классов «буква» (любая Unicode-буква, **кроме CJK из U+3400–U+4DBF**), «цифра», `_`. Один токен.
   5. **Эмодзи** — отдельный класс токенов, не «слово» и не «разделитель». Один эмодзи = один токен. Границы кластера определяются через `java.text.BreakIterator.getCharacterInstance()` (UAX #29). Это покрывает суррогатные пары, ZWJ-последовательности, variation selectors, модификаторы тона кожи и региональные индикаторы флагов. Эмодзи-токен может быть частью фразы; при подсчёте `L` его длина равна числу code points.
   6. **Разделитель** — максимальная последовательность подряд идущих символов, не входящих ни в класс «слово», ни в класс «эмодзи», ни являющихся частью атомарной единицы экранирования. Один токен.

7. Частоты слов, эмодзи и фраз.
8. Критерий `S` на каждом уровне.

**Формат хранения текстовых токенов в словаре.** Текстовый токен хранит **экранированную** строку (ту, что была получена после 9.1.1). Это гарантирует, что при декомпрессии текстовый токен можно вывести как есть, а вложенные в него экранированные последовательности `§§`/`§#<CJK>` будут корректно распознаны парсером 9.5 и превращены в литеральные `§`/CJK.

### 9.2. Пороги

| Параметр | Обычный режим | Агрессивный режим |
|---|---|---|
| Мин. длина слова | 3 (задаётся режимом) | не меняется |
| Мин. частота | 2 | 2 |
| Мин. частота для кодов ступени 2 | 6 | 3 |
| Мин. длина фразы (в токенах) | 7 | 5 |
| Порог `S` | `thresholdS` (по умолчанию 0) | −2 (принудительно) |

Агрессивный режим меняет только пороги (включая `minFrequencyForStep2`) и минимальную длину фразы, а также принудительно устанавливает `thresholdS = −2`. `minWordLength` задаётся режимом (см. раздел 12.1) и агрессивным режимом не переопределяется.

Агрессивный режим допускает записи, убыточные в моменте, но выгодные в долгосрочной перспективе чата.

### 9.3. Генерация кодов

Две ступени (см. раздел 20):

1. **Ступень 1.** Односимвольные коды из CJK Extension A (U+3400–U+4DBF). Длина кода `C = 1`.
2. **Ступень 2.** Трёхсимвольные коды с префиксом `§`: `§XY`, где `X`, `Y` — CJK. Длина кода `C = 3`.

### 9.4. Замена

1. Замена выполняется строго в порядке, определённом сортировкой кандидатов (см. 8.2.4): по убыванию `S`, при равенстве — по убыванию `L`, при равенстве — по убыванию `F`, при равенстве — лексикографически. Это детерминированный порядок, совпадающий с порядком поиска.
2. Проверка границ слова: замена токена-слова производится, только если соседние токены не являются частью того же слова. Поскольку токенизация уже разделила текст на слова и разделители, замена ведётся **по токенам**, а не по символам; отдельная проверка границ не требуется, кроме случая замены внутри текстового токена (такая замена запрещена).
3. Нормализация регистра — опция (для кода отключается автоматически: код не нормализуется). Нормализация выполняется на этапе токенизации, до подсчёта частот.
4. Гибрид SaberW+ZIP — опция (см. раздел 10.10).

### 9.5. Декомпрессия

Декомпрессия — **один лево-правый проход** по сжатому тексту. Результат работы прохода не пересканируется. Каждая атомарная единица обрабатывается ровно один раз.

**Алгоритм:**

1. Идти по символам сжатого текста слева направо.
2. На каждом шаге:
   - `§§` → вывести литерал `§`, сдвинуться на 2 символа.
   - `§#` и следующий за ним CJK из U+3400–U+4DBF → вывести этот CJK, сдвинуться на 3 символа.
   - `§` и два следующих CJK, образующих код ступени 2 → найти запись с таким кодом в словаре; если найдена — рекурсивно раскрыть её `value` и вывести результат; сдвинуться на 3 символа. Если записи нет — ошибка декомпрессии.
   - `§` в любой другой комбинации → ошибка декомпрессии («одиночный `§` вне допустимых сочетаний»).
   - Одиночный CJK из U+3400–U+4DBF → найти запись ступени 1 с таким кодом; если найдена — рекурсивно раскрыть её `value` и вывести результат; если нет — ошибка декомпрессии.
   - Любой другой символ → вывести как есть, сдвинуться на 1 символ.
3. **Рекурсивное раскрытие `value`.** Для каждого токена значения:
   - токен-код раскрывается той же функцией (рекурсивно);
   - текстовый токен выводится **с обработкой экранирования**: внутри текстового токена лево-правым проходом распознаются `§§` и `§#<CJK>` и заменяются на литеральные `§` и CJK соответственно; остальные символы выводятся как есть. Токен-код внутри текстового токена не встречается (текстовые токены не содержат кодов).
4. Рекурсивное раскрытие `value` не выполняет повторный проход по уже выведенному тексту.
5. **Ограничение глубины рекурсии.** Максимальная глубина рекурсии — 1000. При превышении — ошибка декомпрессии, в лог пишется ERROR.

**Обработка ошибок декомпрессии.** При любой ошибке:
- результат не выводится в поле «Распакованный текст» (поле остаётся пустым или сохраняет прежнее значение — по выбору реализации; в MVP — очищается);
- показывается модальный диалог с кратким описанием и кнопкой «Подробности»;
- ошибка логируется на уровне ERROR.

**Замечание.** Благодаря экранированию на входе (9.1.1) все литеральные `§` и литеральные CJK из диапазона кодов представлены в сжатом тексте в экранированном виде. Это делает лево-правый парсер однозначным.

## 10. Словарь

1. Формат хранения — JSON (через Jackson).
2. **Экспорт текстовый.** Строка = `<код><разделитель><значение>`. Разделитель — первый символ табуляции `\t`. Значение сериализуется как конкатенация токенов: текстовые токены выводятся как есть (экранированные строки), токены-коды — как строки кодов. Затем вся строка экранируется:
   - `\` → `\\`,
   - табуляция → `\t`,
   - перевод строки → `\n`,
   - возврат каретки → `\r`.
   Это позволяет значениям содержать пробелы, табуляции и переносы строк. **Многоуровневые значения сериализуются с сохранением кодов** — такой экспорт пригоден для бота (см. 18), если в инструкции присутствует блок рекурсии.
3. Экспорт «Для бота»: инструкция + словарь + разделитель + сжатый текст. Для первого сообщения — полный словарь, для продолжения — только новые записи (см. раздел 18.2). **Метаданные в экспорт «Для бота» не включаются никогда.**
4. Жизненный цикл: создание, дополнение, запрет удаления применённых записей.
5. Операции: сохранить, загрузить, объединить, дополнить, сократить, оптимизировать, поглощение (см. раздел 10.9).
6. Длина записи не ограничена по умолчанию. Опциональное ограничение задаётся параметром `maxRecordLength` (по умолчанию `-1` — без ограничения) в настройках. Значение проверяется при создании записи; при превышении — запись не создаётся, в лог пишется WARN.
7. Записи с `codeAppliedCount ≥ 1` не удаляются. Записи с `codeAppliedCount = 0` могут быть удалены через «Сократить словарь» — **кроме случаев, когда на них ссылается (прямо или косвенно) хотя бы одна применённая запись**. Для этого ведётся учёт обратных ссылок: перед удалением проверяется, что код не входит в `value` ни одной записи с `codeAppliedCount ≥ 1` (прямо или транзитивно).
8. Опция «Автосокращение при закрытии словаря» (по умолчанию выключена). Срабатывает: при закрытии главного окна, при выходе из программы, при загрузке другого словаря. Во всех случаях — после успешного сохранения текущего словаря.
9. **Операции со словарём:**
   - **Сохранить** — записать текущее состояние в файл.
   - **Загрузить** — прочитать файл и заменить текущее состояние. **Если `measureUnit` загружаемого словаря не совпадает с текущим значением — операция отменяется с сообщением об ошибке.** Файлы с невалидным JSON или отсутствующим `id` отвергаются с сообщением об ошибке.
   - **Объединить** — слить два словаря. Результат:
     - `id` остаётся от первого (текущего) словаря;
     - `createdAt` остаётся от первого словаря;
     - `metadata` сливается:
       - суммы счётчиков `totalCompressions`, `totalDecompressions`, `supplementCount`, `exportCount` складываются;
       - `mergeCount` увеличивается на 1;
       - `chatLinks` и `appliedDates` объединяются без повторов;
       - `note` берётся из первого словаря, если он непустой, иначе из второго;
       - `lastExportIncludedMetadata` сбрасывается в `false`;
       - `sizeBytes`, `entriesCount`, `totalValueChars` пересчитываются при сохранении;
     - **записи сливаются:**
       - если код записи из второго словаря совпадает с кодом записи первого и значения совпадают (с точностью до токенов) — записи объединяются: `frequency` и `codeAppliedCount` суммируются, `addedAt` берётся минимальная, `sentToBot` — логическое И (запись считается отправленной, только если она была отправлена в обоих словарях), `level` пересчитывается по правилам раздела 19;
       - если код совпадает, но значения различаются — запись из второго словаря получает **новый код**: генерируется свободный код той же ступени (1 или 2), не входящий ни в `value`, ни в `code` ни одной записи. **Проверка на вхождение в «текущий текст» не выполняется, так как при объединении понятие «текущий текст» отсутствует; считается, что объединение происходит над пустым текстом.** `level` пересчитывается по правилам раздела 19; `sentToBot` сбрасывается в `false` (новый код не отправлялся);
       - если код не совпадает — запись из второго словаря добавляется как есть, с сохранением всех полей;
     - все ссылки на изменённые коды в `value` других записей обновляются на новые коды;
     - если `measureUnit` не совпадают — операция отменяется с сообщением об ошибке.
   - **Дополнить** — добавить новые записи, найденные в текущем тексте.
   - **Сократить** — удалить записи с `codeAppliedCount = 0`, не защищённые ссылками (см. п. 7).
   - **Оптимизировать** — пересчитать коды записей с `codeAppliedCount = 0` так, чтобы минимизировать суммарную длину. **Алгоритм:**
     1. Собрать множество записей-кандидатов: `codeAppliedCount = 0` и отсутствие ссылок из применённых записей (п. 7).
     2. Собрать множество освобождаемых кодов (коды кандидатов) и множество занятых кодов (коды применённых записей и коды, на которые есть ссылки).
     3. Для каждого кандидата вычислить вес: **суммарное число вхождений его кода в `value` других записей (прямо или транзитивно), умноженное на длину кода кандидата.** Чем выше вес, тем важнее переназначить кандидата на более короткий код.
     4. Жадно переназначить коды кандидатов на свободные коды ступени 1 (если доступны), предпочитая коды с наибольшим весом. Если ступень 1 исчерпана — на свободные коды ступени 2.
     5. Обновить все ссылки в `value` других записей на новые коды.
     6. Критерий остановки: все кандидаты либо переназначены, либо для них нет свободных кодов.
     Применённые записи и записи, на которые есть ссылки, не трогаются.
   - **Поглощение** — заменить текущий словарь готовым словарём из внешнего источника. Правила:
     - если `measureUnit` поглощаемого словаря не совпадает с текущим — операция отменяется с сообщением об ошибке;
     - если в поглощаемом словаре есть «висячие» ссылки (код в `value` не существует среди записей) — операция отменяется с сообщением об ошибке;
     - `id` заменяется на новый (генерируется по правилам раздела 5);
     - `createdAt` берётся от поглощаемого словаря;
     - `entries` берутся из поглощаемого; все записи получают `sentToBot = false`; поля `frequency`, `codeAppliedCount`, `addedAt`, `level` **сохраняются из поглощаемого словаря**;
     - `metadata` собирается так: `note` — из поглощаемого; `chatLinks`, `appliedDates` — из поглощаемого; счётчики `totalCompressions`, `totalDecompressions`, `supplementCount`, `mergeCount`, `exportCount` — сохраняются от текущего словаря; `lastExportIncludedMetadata` сбрасывается в `false`; `sizeBytes`, `entriesCount`, `totalValueChars` пересчитываются при сохранении.
10. **Гибрид SaberW+ZIP.** Опция. Сжатый текст дополнительно упаковывается в ZIP-архив вместе со словарём и метаданными, файл получает расширение `.saberwz`. Формат:
    ```
    archive.saberwz
    ├── dictionary.saberw.json   (тот же формат, что в 17.1; metadata внутри)
    ├── metadata.json            (копия объекта metadata; включается, только если transferMetadataOnExport == true)
    ├── payload.txt              (сжатый текст, UTF-8)
    └── payload.bin              (опционально, если исходник бинарный; хранится как есть)
    ```
    Формат предназначен для передачи между экземплярами SaberW 2 и для хранения бинарных исходников. Боту не отправляется. Распаковка — обратная операция: чтение архива, извлечение словаря, декомпрессия текста.

### 11.1. Главное окно

1. Поля: исходный текст, сжатый текст, словарь, метаданные.

   - **Пример** — загружает в поле «Исходный текст» встроенный демонстрационный текст (русский + английский + эмодзи). Текст хранится в ресурсе `templates/example.txt`.
   - **Копировать словарь** — копирует в буфер текстовый экспорт словаря (см. 10.2). Увеличивает `exportCount`.

Устанавливает `sentToBot = true` у новых записей (то есть у всех записей с `sentToBot == false` на момент копирования). **`lastExportIncludedMetadata` не обновляет.**

| Ctrl+Shift+C | Копировать результат | `copyResult` |
| Ctrl+Alt+C | Копировать со словарём | `copyWithDictionary` |
| Ctrl+B | Для бота | `exportForBot` |
| Ctrl+Shift+S | Сохранить сжатый результат в файл | `saveResult` |
| Ctrl+Shift+O | Открыть файл | `openFile` |
| Ctrl+S | Сохранить словарь | `saveDictionary` |
| Ctrl+Shift+L | Загрузить словарь | `loadDictionary` |
| Ctrl+Shift+K | Копировать словарь | `copyDictionary` |
| Ctrl+Shift+W | SaberW+ZIP | `exportZip` |
| Ctrl+E | Пример | `loadExample` |
| Ctrl+Shift+A | Автонастройка | `autoTune` |
| Ctrl+, | Открыть окно настроек | `openSettings` |
| Ctrl+H | Открыть справку | `openHelp` |
| Ctrl+Shift+D | Дополнить словарь | `supplementDictionary` |
| Esc | Остановить поиск (если идёт) | `stopSearch` |
| Ctrl+Q | Выход | `exit` |

Все комбинации прописаны в ресурсном файле `hotkeys.properties`.

**Формат:** `action.id=<Modifier>+<Modifier>+<Key>`, где `action.id` соответствует идентификатору действия в меню (см. таблицу выше). Модификаторы — `Ctrl`, `Shift`, `Alt`, `Meta`. Ключ — `Key` (латинская буква), `Enter`, `Comma`, `Escape` и т. п. Парсер — общий с настройками.

**Парсер горячих клавиш.** Разбирает строку формата `<Modifier>+...+<Key>`. Неизвестный модификатор или ключ — ошибка конфигурации, в лог пишется WARN, комбинация игнорируется. Если для одного `action.id` указано несколько строк — используется первая, остальные игнорируются с WARN. Если две разные действия имеют одну комбинацию — конфликт разрешается в пользу действия, объявленного в таблице выше (приоритет фиксирован порядком таблицы), в лог пишется WARN.

**Правило разрешения конфликтов.** В текстовых полях стандартные комбинации (`Ctrl+C`, `Ctrl+V`, `Ctrl+X`, `Ctrl+A`, `Ctrl+Z`, `Ctrl+Y`, `Ctrl+Shift+Z`) обрабатываются самим полем (нативное поведение). Действия программы с этими же комбинациями вызываются только при фокусе вне текстового поля либо через пункты меню. Комбинации с `Shift`/`Alt` (см. таблицу) работают всегда, **кроме `Ctrl+Shift+Z`** (зарезервирована под redo в текстовых полях; для SaberW+ZIP используется `Ctrl+Shift+W`). Комбинация `Esc` обрабатывается только когда идёт поиск; в остальное время передаётся фокус-владельцу (закрытие диалогов и т. п.).

### 11.4. Файлы

- Открывать: `.txt`, `.md`, `.java`, `.json`, `.xml`, `.csv`, `.saberwz`.
- Сохранять: результат, словарь (JSON), архив `.saberwz`. Метаданные отдельным файлом не сохраняются — они всегда часть JSON словаря (см. 17.1).
- Бинарные файлы — через гибридный режим (см. 10.10).

## 12. Окно настроек

1. Отдельное модальное окно (диалог), вызывается из главного меню.
2. Содержит:
   - параметры сжатия (мин. длина слова, мин. частота, мин. частота для кодов ступени 2, макс. токенов во фразе, мин. длина фразы в токенах, порог `S`, нормализация, агрессивное сжатие, игнорировать комментарии),

   - выбор папки для хранения файлов (`filesFolder`),
   - флаг «Сохранять сообщения»,
   - флаг «Сохранять сообщения в сжатом виде (ZIP)»,
   - флаг «Переносить метаданные при экспорте словаря» (`transferMetadataOnExport`; влияет только на `.saberwz`, см. 6),
   - выбор языка инструкции для бота (русский / английский),
   - секция «Сохранённые сообщения»: кнопки «Открыть папку», «Удалить сообщения старше N дней», «Удалить все сообщения» (с подтверждением), флаг «Автоматически удалять сообщения старше N дней»,
   - поле для заметки по текущему словарю,
   - кнопку **«Фа»** (см. раздел 13),
   - кнопки «Сохранить», «Отмена», «Применить», «Сбросить к умолчаниям».
3. **Семантика кнопок:**
   - **«Применить»** — применить изменения к текущему сеансу, не закрывая окно и не записывая в `settings.json`.
   - **«Сохранить»** — применить изменения, записать в `settings.json`, закрыть окно.
   - **«Отмена»** — откатить все изменения, сделанные с момента последнего «Применить» или открытия окна, закрыть окно.
   - **«Сбросить к умолчаниям»** — установить значения по умолчанию (без немедленного применения; требуется «Применить» или «Сохранить»).
4. **Игнорирование комментариев.** Флаг `ignoreComments` (по умолчанию выключен). При включении из текста исключаются фрагменты, распознанные как комментарии, согласно языку, определённому эвристикой (см. 12.2). Исключённые фрагменты не участвуют в подсчёте частот и не заменяются кодами, но **проходят через экранирование 9.1.1** — иначе нарушится инвариант «все литеральные `§` и CJK из диапазона кодов экранированы». Экранированные комментарии остаются в тексте как обычные разделители/слова и при декомпрессии возвращаются в исходном виде. Round-trip сохраняется.

### 12.1. Режимы сжатия

Режим — это именованный набор параметров сжатия. При ручном изменении любого параметра режим автоматически переключается в `manual`.

| Режим | `mode` | Мин. длина слова | Мин. частота | Мин. частота для ступени 2 | Мин. длина фразы | Нормализация | Агрессивное | Применение |
|---|---|---|---|---|---|---|---|---|
| Максимальное сжатие | `max-cjk` | 3 | 2 | 6 | 7 | вкл | выкл | длинные тексты, обычные чаты |
| Программный код | `code` | 4 | 2 | 6 | 7 | выкл | выкл | исходный код, разметка |
| Быстрая переписка | `chat` | 3 | 2 | 6 | 5 | вкл | выкл | короткие сообщения |
| Ручной | `manual` | — | — | — | — | — | — | параметры заданы вручную |

Остальные параметры (`maxPhraseTokens`, `thresholdS`, `ignoreComments`, `measureUnit`, `maxRecordLength`) не входят в пресеты и берутся из текущих значений; при выборе пресета они не сбрасываются. `aggressive` при выборе `code` можно включить вручную — это понизит пороги, но не тронет `minWordLength = 4` и принудительно установит `thresholdS = −2`.

### 12.2. Эвристика определения языка для `ignoreComments`

Правила применяются с учётом приоритета: если сработало правило 1 (HTML/XML), правила 2 и 3 не применяются. Если сработало правило 2 (Java/C/C++/JS), правило 3 не применяется.

1. **HTML/XML.** Если текст содержит `<!--` — применяются правила HTML/XML (`<!-- -->`).
2. **Java/C/C++/JS.** Если текст содержит `//` или `/*` — применяются правила Java/C/C++/JS. **Уточнение:** `//` считается началом комментария, только если непосредственно перед ним **не стоит `:`** (это исключает `http://`, `https://`, `ftp://` и подобные URL). `/*` считается началом комментария всегда.
3. **Python.** Применяется только если не сработали правила 1 и 2, И текст **не содержит директив препроцессора C** (строки, начинающиеся с `#include`, `#define`, `#ifdef`, `#ifndef`, `#if`, `#else`, `#elif`, `#endif`, `#pragma`, `#error`, `#warning`, `#line`, `#undef`). Тогда строки, начинающиеся с `#` (возможно, с пробелами) или содержащие `# `, считаются Python-комментариями до конца строки.
4. Если ни одно не сработало — `ignoreComments` игнорируется (комментарии не вырезаются).
5. Пользователь может вручную указать язык в окне настроек (поле `commentsLanguage`: `auto`, `java`, `python`, `html`). По умолчанию — `auto`. При ручном выборе применяются только правила соответствующего языка, без проверки маркеров.

Многострочные комментарии (HTML, `/* */`) вырезаются целиком, включая все строки между маркерами. Однострочные (`//`, `#`) — до конца строки.

**Экранирование комментариев.** После вырезания фрагменты комментариев проходят экранирование 9.1.1 (как и весь остальной текст). При сжатии они не заменяются кодами, но остаются в тексте в экранированном виде. При декомпрессии возвращаются в исходный вид.

**Ограничения MVP.** Строковые литералы не анализируются: `"http://"` внутри строки может быть ошибочно принято за начало комментария. Вложенные конструкции и многострочные комментарии с вложением не разбираются. Расширенная эвристика — вне MVP (раздел 25).

**MVP.** Базовая эвристика 12.2 и `ignoreComments` входят в MVP. Расширенная эвристика (уточнение языка, разбор вложенных конструкций, корректная обработка строковых литералов) — вне MVP (раздел 25).

## 14. Сохранение сообщений

1. **По умолчанию сохранение включено.**
2. Сохраняется каждое сообщение **в момент нажатия** «Сжать» (направление `out`) и «Распаковать» (направление `in`). Копирование в буфер повторно не сохраняет. Если сжатие/распаковка завершились ошибкой — сообщение не сохраняется.
   - При «Сжать»: сохраняется **исходный (человекочитаемый) текст**, который пользователь намерен отправить боту.
   - При «Распаковать»: сохраняется **распакованный текст** (ответ бота в человекочитаемом виде).
   - Если флаг «Сохранять сообщения в сжатом виде (ZIP)» включён, в ZIP-архив дополнительно кладётся второй файл: для `out` — сжатый текст, для `in` — исходный (сжатый) ответ бота.
3. Папка сохранения:
   - Windows: `%APPDATA%\SaberW2\messages\`
   - Linux: `~/.saberw2/messages/`
   - macOS: `~/Library/Application Support/SaberW2/messages/`
4. **Кодировка — UTF-8.**
5. **Расширение:**
   - если флаг «Сохранять сообщения в сжатом виде (ZIP)» включён — `.zip` (и для `out`, и для `in`),
   - если выключен — `.txt`.
6. **Имя файла:**
   - при наличии словаря: `<ИД>_<YYYY-MM-DD>_<HH-MM-SS-SSS>_<направление>.<ext>`,
   - при отсутствии словаря: `no-dict_<YYYY-MM-DD>_<HH-MM-SS-SSS>_<направление>.<ext>`.
   - `направление` — `out` (отправлено боту) или `in` (получено от бота).
   - Миллисекунды в имени защищают от коллизий.
   - Разбор имени файла при автоочистке: первый компонент — ИД или `no-dict`; второй — дата `YYYY-MM-DD`; третий — время; четвёртый — направление. Поскольку `-` и `_` исключены из алфавита ИД (см. раздел 5), разбор однозначен.
7. **Случай, когда словарь ещё не создан.** Сообщение сохраняется с префиксом `no-dict_`. После создания словаря это сообщение не переименовывается.
8. **Внутри ZIP** — один или два текстовых файла:
   - `<basename>.txt` — основной контент (см. п. 2), где `<basename>` — имя архива без расширения `.zip`;
   - `<basename>_raw.txt` — второй контент (сжатый для `out`, исходный сжатый для `in`), если применимо.
9. Пользователь может отключить сохранение в настройках.
10. Пользователь может отключить ZIP-упаковку в настройках.
11. Автоочистка по умолчанию выключена.
12. **Дата для автоочистки** — берётся из имени файла: первый компонент после ИД/`no-dict`, имеющий формат `YYYY-MM-DD`. Если имя не соответствует шаблону — используется дата изменения файла. Для ZIP-архивов используется дата изменения самого архива (внутренние имена файлов не разбираются). **Файлы, имя которых не соответствует шаблону и которые не удаётся однозначно датировать, при автоочистке пропускаются (не удаляются).**
13. UI для очистки — в окне настроек (см. раздел 12).

## 16. Хранение данных и пути

**Настройки программы** всегда хранятся по фиксированному системному пути, независимо от `filesFolder`:
- Windows: `%APPDATA%\SaberW2\settings.json`
- Linux: `~/.saberw2/settings.json`
- macOS: `~/Library/Application Support/SaberW2/settings.json`

**Если `System.getProperty("user.home")` недоступен** — используется текущая рабочая директория: `<cwd>/SaberW2/settings.json` и `<cwd>/SaberW2/` как корень данных по умолчанию. В лог пишется WARN.

**Корневая папка данных** (для `dicts/`, `messages/`, `logs/` и т. д.) определяется `PathResolver`:
1. Если задана `filesFolder` в `settings.json` — использовать её.
2. Иначе — системный путь по умолчанию:
   - Windows: `%APPDATA%\SaberW2\`
   - macOS: `~/Library/Application Support/SaberW2/`
   - Linux и прочие Unix-подобные: `~/.saberw2/`
3. Если `user.home` недоступен — `<cwd>/SaberW2/`.

Таким образом, курица-яйцо устранена: `settings.json` ищется по фиксированному пути, а `filesFolder` управляет только папкой данных.

| Файл | Расположение |
|---|---|
| Настройки | фиксированный системный путь (см. выше) |
| Словари (основное) | `<root>/dicts/` |
| Словари (резерв, если основная папка недоступна на запись) | `<root>/dicts-backup/` |
| Сообщения | `<root>/messages/` |
| Логи | `<root>/logs/` |

**Резервная папка словарей (`dicts-backup/`).** Используется, когда основная папка `<root>/dicts/` недоступна на запись (проверка — попытка создать файл в папке; при неудаче — переключение на резервную). При переключении:
- при чтении словаря: если запрошенный файл отсутствует в `<root>/dicts/`, но есть в `<root>/dicts-backup/`, он читается оттуда;
- при записи: если запись в `<root>/dicts/` невозможна, файл пишется в `<root>/dicts-backup/`, пользователь уведомляется в логе (WARN) и в UI (индикатор в статусной строке);
- **если обе папки недоступны на запись — операция сохранения отменяется, пользователю показывается модальный диалог с ошибкой; словарь не сохраняется;**
- уникальность ИД проверяется в обеих папках (см. раздел 5);
- при следующем запуске, если основная папка снова доступна, резервная не мигрируется автоматически — файлы остаются на своих местах; поиск при загрузке выполняется в обеих папках. **Пользователь может вручную перенести файлы из резервной папки в основную; программа не делает этого автоматически.**

**Логи:** текстовый файл `saberw.log`, ротация по 10 МБ, хранится 5 последних файлов. Формат строки: `<ISO-8601 timestamp> <LEVEL> <logger> <message>`. Стектрейсы исключений записываются отдельными строками после основной, с отступом в 4 пробела. Ошибки записи в лог игнорируются (без рекурсии). **Логируются только сообщения уровня WARN и выше (WARN, ERROR).** Все ошибки (ERROR) и предупреждения (WARN) логируются.

**Обработка ошибок в UI.** Все ошибки логируются. Пользователю показываются модальные диалоги с кратким описанием и кнопкой «Подробности» (раскрывает стектрейс). Критические ошибки (невозможность сохранить словарь, чтение JSON) — с кнопкой «OK» и записью в лог. Ошибки уровня WARN — только в лог, без диалога.

## 17. JSON-схемы

### 17.1. Файл словаря и метаданных

Один файл. Расширение — `.saberw.json` или просто `.json`.

**Корневой объект:**

```json
{
  "format": "saberw-dictionary",
  "formatVersion": 1,
  "id": "A7xK2m",
  "createdAt": "2026-10-12T14:30:00Z",
  "dictionary": { ... },
  "metadata": { ... }
}
```

**Объект `dictionary`:**

```json
{
  "updatedAt": "2026-10-13T09:12:44Z",
  "measureUnit": "characters",
  "entries": [
    {
      "code": "㐀",
      "value": [
        {"type": "text", "text": "программа"}
      ],
      "level": 1,
      "frequency": 12,
      "codeAppliedCount": 12,
      "addedAt": "2026-10-12T14:30:00Z",
      "sentToBot": true
    },
    {
      "code": "§㐀㐁",
      "value": [
        {"type": "code", "code": "㐀"},
        {"type": "text", "text": " "},
        {"type": "code", "code": "㐁"}
      ],
      "level": 2,
      "frequency": 3,
      "codeAppliedCount": 3,
      "addedAt": "2026-10-12T14:40:00Z",
      "sentToBot": false
    }
  ]
}
```

Поля записи:
- `code` — код (1 символ для ступени 1, 3 символа `§XY` для ступени 2).
- `value` — массив токенов. Токен: `{"type": "text", "text": "..."}` или `{"type": "code", "code": "..."}`. **Текстовые токены хранят экранированные строки** (результат 9.1.1), поэтому внутри них возможны последовательности `§§` и `§#<CJK>`.
- `level` — уровень многоуровневого сжатия (1 — базовый; слова всегда 1; фразы — 1 или выше, см. раздел 3 и 19).
- `frequency` — сколько раз встретилось на уровне, где запись была создана (для уровня 1 — в исходном тексте; для уровня N — в тексте, уже сжатом до уровня N−1).
- `codeAppliedCount` — сколько раз код применялся **напрямую** при сжатии. Косвенные применения через `value` других применённых записей не учитываются в этом поле, но защищают от удаления (см. 10.7).
- `addedAt` — дата добавления.
- `sentToBot` — была ли запись отправлена боту (в составе «Первого сообщения» или «Дополнения») или скопирована со словарём. По умолчанию `false`. Сохраняется в JSON.

Поле `refersTo` отсутствует: список кодов выводится из `value`.

**Объект `metadata`:**

```json
{
  "note": "Чат по проекту SaberW 2",
  "chatLinks": ["https://chat.deepseek.com/..."],
  "appliedDates": ["2026-10-12", "2026-10-13"],
  "totalCompressions": 7,
  "totalDecompressions": 5,
  "supplementCount": 3,
  "mergeCount": 0,
  "exportCount": 1,
  "lastExportIncludedMetadata": true,
  "sizeBytes": 4096,
  "entriesCount": 45,
  "totalValueChars": 1200
}
```

`createdAt` хранится только на верхнем уровне. `updatedAt` — в объекте `dictionary`.

**Семантика `current` и `defaults`.**
- `current` — **текущие параметры сжатия**, используемые в сессии. При запуске программы параметры берутся из `current`. При изменении параметров в сессии и нажатии «Сохранить» они записываются в `current`. При нажатии «Применить» — только в память.

**`lastDictionaryPath` и `lastExportPath`** — абсолютные пути. Если путь недоступен, он игнорируется, диалог открывается в папке по умолчанию.

Текстовый файл. Формат:

```
<инструкция>

㐁	сжатие текста

___
<сжатый текст>
```

Разделитель строк словаря — табуляция `\t`. Разделитель блоков — три подчёркивания `___` (может быть заменён, см. 18.6). **Метаданные не включаются.**

## 18. Инструкция для бота

### 18.1. Назначение

Инструкция для бота — короткий текст, который предшествует словарю и сжатому тексту в сообщении, отправляемом в чат нейросети. Её задача — объяснить нейросети, как читать сжатый текст.

Инструкция генерируется программой автоматически, подстраивается под текущие настройки сжатия и включается в экспорт «Для бота».

### 18.2. Сценарии

**Первое сообщение.** Используется, когда установлен чекбокс «Первое сообщение». Содержит **полную инструкцию и полный словарь**.

**Продолжение сессии.** Используется, когда чекбокс «Первое сообщение» снят. Содержит **только новые записи словаря** (те, у которых `sentToBot == false`) и минимальный текст.

Автоматическое определение «нового чата» программой не выполняется — признак «новый чат» пользователь задаёт вручную.

**Автоустановка чекбокса.** Если словарь создан только что и ни разу не применялся (`totalCompressions == 0 && supplementCount == 0`), чекбокс автоматически включается (см. 18.8). Если словарь уже применялся, чекбокс автоматически снимается при загрузке.

Продолжение сессии:

```
Дополнение словаря:
㐃	новое слово
㐄	новая фраза
___
<сжатый текст>
```

Если в текущем сжатии нет новых записей:

```
Сообщение:
___
<сжатый текст>
```

**Признак «новой записи».** Запись считается новой, если `sentToBot == false`. Флаг становится `true` при экспорте «Для бота» (кнопка или горячая клавиша) и при копировании со словарём. Обратно в `false` флаг не переводится. Флаг сохраняется в JSON. При перезапуске программы состояние восстанавливается из файла.

### 18.3. Автоматическая сборка

```
если чекбокс «Первое сообщение» установлен:
    собрать полную инструкцию из блоков
    + полный словарь
    + разделитель
    + сжатый текст
иначе:
    если есть новые записи словаря (sentToBot == false):
        заголовок "Дополнение словаря:"
        + новые записи
        + разделитель
        + сжатый текст
    иначе:
        заголовок "Сообщение:"
        + разделитель
        + сжатый текст
```

Если чекбокс снят, но словарь ещё ни разу не применялся (`totalCompressions == 0 && supplementCount == 0`), программа показывает предупреждение «Словарь ещё не применялся. Рекомендуется отправить первое сообщение с полной инструкцией» и предлагает включить чекбокс. Если пользователь отказывается — используется ветка «продолжение» (вопреки рекомендации).

**Блоки полной инструкции (каждый — отдельный ресурсный файл):**

1. `bot-block-base.ru.txt` — базовый блок, всегда.
2. `bot-block-recursion.ru.txt` — **если есть хотя бы одна запись, в значении которой присутствует токен-код** (то есть уровень ≥ 2 или фраза уровня 1, ссылающаяся на слово).
3. `bot-block-normalization.ru.txt` — если активна нормализация регистра.
4. `bot-block-supplement.ru.txt` — если словарь был дополнен.

### 18.4. Хранение шаблонов

Шаблоны хранятся в ресурсных файлах:

```
src/main/resources/templates/
├── bot-block-base.ru.txt
├── bot-block-base.en.txt          (зарезервирован, в MVP не используется)
├── bot-block-recursion.ru.txt
├── bot-block-normalization.ru.txt
├── bot-block-supplement.ru.txt
├── bot-instruction-minimal.ru.txt
├── bot-instruction-minimal.en.txt (зарезервирован, в MVP не используется)
└── example.txt
```

- `bot-instruction-minimal.*.txt` — готовый минимальный шаблон для продолжения сессии (без блоков).
- Остальные — блоки полной инструкции, собираются конкатенацией в порядке 1–4.

Для MVP — только русский. Английский добавляется позже.

### 18.5. Язык инструкции

Язык выбирается в настройках (поле `botInstructionLanguage`):
- `ru` — русский (по умолчанию),
- `en` — английский (добавляется позже; в MVP выбор есть, но `en` использует `ru`-файлы с предупреждением в логе).

### 18.6. Защита от конфликта разделителя

Разделитель по умолчанию — `___`. При генерации программа проверяет, что **выбранный разделитель** не встречается в словаре, сжатом тексте и инструкции. Если встречается — он заменяется последовательно на `~~~`, `###`, `===`, `***`. Первый вариант, не встречающийся во всех трёх блоках, используется; замена фиксируется в инструкции автоматически. Если все четыре варианта встречаются — генерируется ошибка и экспорт отменяется. **Пользовательский разделитель в MVP не поддерживается.**

### 18.7. Автосброс чекбокса «Первое сообщение»

Чекбокс автоматически снимается после нажатия кнопки «Для бота» или после копирования со словарём. Программа не знает, отправлено ли сообщение — она реагирует только на действие пользователя внутри программы.

### 18.8. Автоустановка чекбокса

Если словарь только что создан и ни разу не применялся (`totalCompressions == 0 && supplementCount == 0`) — чекбокс автоматически включается. При загрузке словаря, который уже применялся (`totalCompressions > 0 || supplementCount > 0`), чекбокс автоматически снимается.

## 19. Защита от циклов

1. Каждая запись словаря имеет поле `level`.
2. Значение записи уровня `N` может ссылаться только на коды уровня `≤ N−1`.
3. **Исключение:** записи-слова (уровень 1) могут быть указаны в значении любой записи-фразы любого уровня, включая уровень 1. Это возможно, потому что слова не содержат ссылок на коды, и цикл через них невозможен.
4. Ссылка на код того же уровня или более высокого запрещена (кроме исключения п. 3).
5. Перед добавлением записи уровня `N` программа проверяет: все коды в `value` имеют `level ≤ N−1`, **либо являются словами уровня 1**.
6. Проверка выполняется как при создании, так и при загрузке JSON.
7. **Проверка ацикличности** — обход графа зависимостей в глубину с пометкой посещённых узлов. Если найден цикл — **запись отвергается, в лог пишется предупреждение, пользователю показывается сообщение. Остальные записи загружаются; файл не отвергается целиком.**
8. **Защита от «висячих» ссылок.** При загрузке JSON проверяется, что каждый `code` в токенах `value` существует в словаре. Если нет — запись отвергается с сообщением, остальные загружаются.
9. **Защита от удаления «опорных» кодов.** Перед удалением или сменой кода записи `X` программа проверяет, что ни одна применённая запись (`codeAppliedCount ≥ 1`) не содержит `X` в своём `value` (прямо или транзитивно). Если содержит — операция отменяется.
10. **Ограничение глубины рекурсии при декомпрессии** — см. 9.5.5.

## 20. Исчерпание кодов

Две ступени:

**Ступень 1 — односимвольные коды.** CJK Extension A: U+3400–U+4DBF, около 6 592 символов. Из них исключаются символы, уже выданные как коды. Символы, встречающиеся в исходном тексте, **не исключаются**: они экранированы в `§#<символ>` и не могут быть спутаны с кодами, а их исключение лишь уменьшает доступный набор без необходимости. Обычно доступно около 6 500 символов. Длина кода `C = 1`.

**Ступень 2 — префиксные коды.** Когда односимвольные исчерпаны, используются пары символов с префиксом `§`: `§㐀㐀`, `§㐀㐁` и так далее. Количество возможных пар — около 43 миллионов. Длина кода `C = 3`.

**Замечание.** Символ `§` вне префикса кода и вне экранирования в сжатом тексте недопустим. Литеральные `§` и литеральные CJK из диапазона кодов представлены в экранированном виде (`§§`, `§#<символ>`).

Пользователь уведомляется в строке статистики о текущей ступени.

## 22. Нефункциональные требования

1. Java 21+, Maven.
2. Внешние зависимости: Jackson (JSON), JUnit 5 (тесты), Launch4j (сборка EXE).
3. Производительность:
   - Текст 1 МБ в режиме `max-cjk` без многоуровневого поиска (только уровень 1) — ≤ 5 секунд на машине с 4 ГБ ОЗУ и CPU уровня Intel i3. При недостижении — допустимо ослабить до 10 секунд при документировании.
   - Многоуровневое сжатие без ограничения длины фразы — время не гарантируется. Защита: ленивый режим через 10 секунд, прогресс-бар, кнопка «Остановить».
4. Устойчивость к разным языкам и эмодзи.
5. GUI не падает при ошибках.
6. Компактный экспорт для бота.
7. Кроссплатформенность.
8. The Unlicense.

### 22.1. Защита от долгих вычислений

1. **Ленивый режим после 10 секунд.** Рабочий поток переводится в низкий приоритет (`Thread.setPriority(Thread.MIN_PRIORITY)`). Временные структуры (суффиксный массив, хеш-таблицы промежуточных кандидатов) освобождаются после каждой итерации. Интерфейс остаётся отзывчивым.
2. **Продолжение в фоне при закрытии окна.** Вычисления продолжаются в фоновом потоке (`daemon=false`). JVM не завершится до окончания работы потока; в трее показывается уведомление, приложение скрывается. По завершении словарь сохраняется автоматически, пользователь получает уведомление в системном трее и приложение завершается. **Прерывание из трея:** в контекстном меню иконки в трее доступен пункт «Остановить поиск», эквивалентный кнопке в главном окне. **Явный выход** через меню «Файл → Выход» (Ctrl+Q): пользователю показывается диалог с выбором «Дождаться завершения», «Прервать и выйти», «Отмена». **При завершении ОС** поток прерывается принудительно; промежуточный словарь может быть потерян — это осознанное упрощение.
3. **Прерывание пользователем.** Кнопка «Остановить поиск» доступна всегда после старта. При нажатии вычисления останавливаются на границе текущей итерации, промежуточный словарь сохраняется в `<root>/dicts/interrupted-<timestamp>.saberw.json`, где `<timestamp>` — `yyyyMMdd-HHmmss` (без символов, недопустимых в именах файлов Windows). Пользователю предлагается применить незаконченный словарь или продолжить поиск позже. **Граница итерации** — момент, когда текущий кандидат полностью обработан (все его непересекающиеся вхождения заменены), а следующий ещё не начат.
4. **Прогресс-бар.** Появляется через 10 секунд. Показывает текущий уровень, количество обработанных кандидатов, примерную оценку до конца. **Оценка до конца** вычисляется как `(общее_число_кандидатов − обработано) × среднее_время_на_кандидата`, где среднее время считается по уже обработанным кандидатам. При малом числе обработанных кандидатов оценка может быть неточной.

**Отнесение к этапам.** Пункты 22.1.1–22.1.4 относятся к этапу «GUI и настройки» (см. раздел 24.2). В MVP поиск выполняется синхронно в EDT с отключением кнопок на время работы.

## 23. Критерии приёмки

### 23.1. Критерии MVP

1. **Round-trip побуквенно** при выключенной нормализации регистра. `decompress(compress(text)) == text` для набора эталонных текстов (русский, английский, Java-код, смешанный, с эмодзи, **с CJK из диапазона кодов**, **с литеральным `§`**, **с `§#` в исходном тексте**).
2. **Ни один код (как строка) не встречается в подготовленном (экранированном) тексте.** Литеральные CJK и `§` экранированы. Экранированные последовательности `§§` и `§#<CJK>` не разрываются при замене (см. 9.1.2).
3. **Все записи словаря проходят `S ≥ порог`.** Порог по умолчанию 0. В агрессивном режиме порог = −2.
4. **Все слова с `L ≥ minWordLength` и `S ≥ порог` и все фразы с длиной ≥ `minPhraseLength` и `S ≥ порог`, которые не перекрываются с уже выбранными кандидатами, заменены кодами** (с учётом детерминированного тай-брейка из 8.2.4). Остальные остаются как есть.
5. **ИД уникален (регистронезависимо) и стабилен.**
6. **Метаданные сохраняются и загружаются.**
7. **Формат экспорта «Для бота» соответствует шаблону.** Все обязательные блоки присутствуют. Метаданные не включены.
8. **Выбранный разделитель не встречается в словаре, сжатом тексте и инструкции.**
9. **Декомпрессия корректно обрабатывает `§§`, `§#X`, `§XY` и одиночный CJK** лево-правым парсером без повторного сканирования вывода, в том числе внутри рекурсивно раскрываемых значений.
10. **При перезапуске программы флаг `sentToBot` восстанавливается корректно**, и продолжение сессии не отправляет уже отправленные записи.
11. **Многоуровневые записи корректно экспортируются в текстовом виде** с сохранением кодов, и обратно в JSON (через загрузку JSON, не через текстовый импорт — текстовый экспорт только для чтения человеком и ботом).

### 23.2. Критерии полной версии

1. **Многоуровневое сжатие работает.** Целый повторяющийся блок (например, «Обломов × 3») кодируется одним кодом верхнего уровня; запись уровня 2 ссылается на коды уровня 1.
2. **Настройки, геометрия и цвет сохраняются.**
3. **Спиннер шрифта работает в каждом окне** (кроме модальных диалогов подтверждения и информационных).
4. **Кнопка «Фа» открывает папку или предлагает её создать.**
5. **Сохранение сообщений работает.** Файлы создаются в правильной папке с правильным именем, и для `out`, и для `in`.
6. **Автонастройка корректно определяет тип текста и применяет параметры.**
7. **Прогресс-бар появляется через 10 секунд, кнопка «Остановить поиск» работает.**
8. **Гибрид SaberW+ZIP работает.** Файл `.saberwz` создаётся и читается обратно.
9. **Удаление и оптимизация неприменённых записей не ломает применённые.** Проверка на защиту от «висячих» ссылок (19.8–19.9).
10. **Объединение и оптимизация корректно обновляют ссылки** в `value` других записей.
11. **Поглощение сохраняет метрики текущего словаря и берёт записи/метаданные из поглощаемого** согласно 10.9; при несовпадении `measureUnit` или наличии «висячих» ссылок операция отменяется.
12. **`ignoreComments` не ломает round-trip** даже при наличии `§` или CJK в комментариях.
13. **Фразы уровня 1 корректно ссылаются на слова уровня 1**, и загрузка JSON не отвергает такие записи (19.3, 19.5).

Функциональный тест с реальной моделью — не входит в критерии приёмки (см. раздел 25.10).

## 26. Риски

1. Оценка в символах ≠ в токенах.
2. CJK может плохо пониматься без инструкции.
3. Малые тексты не окупают словарь.
4. Коллизии кодов.
5. Нормализация необратима — round-trip побуквенно только при выключенной нормализации.
6. Метаданные раздувают экспорт — нужна опция `transferMetadataOnExport` (для `.saberwz`).
7. Класс-бог может появиться стихийно — нужен code review.
8. Экранирование `§` и CJK нужно реализовать аккуратно; ошибка ломает round-trip. В частности, атомарность единиц экранирования при токенизации (9.1.2) и обработка экранирования внутри текстовых токенов при декомпрессии (9.5) — критичные места.
9. Смешение единиц измерения в одном словаре — запрещено, проверка при загрузке, объединении и поглощении.
10. Горячие клавиши могут конфликтовать со стандартным поведением текстовых полей — см. правило в разделе 11.3.
11. Регистронезависимые файловые системы могут привести к коллизии ИД — проверка выполняется регистронезависимо.
12. Поток `daemon=false` может помешать завершению приложения — поведение описано в 22.1.2. При завершении ОС поток прерывается принудительно, промежуточный словарь может быть потерян.
13. Токенизация кодов при многоуровневом сжатии — реализована через атомарные токены (см. 8.1), но требует внимательного тестирования.
14. Эвристика `ignoreComments` может ошибочно вырезать части текста (например, `http://` в Python-комментарии). В MVP добавлена защита от C-препроцессора и от `://` в правиле Java/C. Строковые литералы не анализируются.
15. **Практический предел длины последовательности (8.2.6)** при `maxPhraseTokens ≤ 0` может отсечь редкие длинные повторы. При необходимости предел можно поднять; в MVP он равен половине длины текста.
16. **Автоочистка сообщений** работает с ZIP-архивами по дате изменения файла — если пользователь переносит архивы, дата может измениться. Это осознанное упрощение. Файлы, имя которых не соответствует шаблону, при автоочистке пропускаются.
17. **Производительность суффиксного массива.** Для текстов 1 МБ и более построение и перестроение суффиксного массива может быть дорогим. В MVP допускается ограничение `maxPhraseTokens` и/или переход к эвристическому поиску при превышении порога времени (см. 22.1).
18. **Дублирование режимов.** Режимы `max-cjk` и `chat` различаются только `minPhraseLength` (7 vs 5). При необходимости в будущем можно добавить различие по `minWordLength` или иным параметрам.
19. **`BreakIterator.getCharacterInstance()`** не гарантирует полную поддержку extended grapheme clusters (ZWJ-последовательности, флаги, модификаторы тона) на всех платформах. В MVP это осознанное упрощение.
20. **Глубина рекурсии при декомпрессии** ограничена 1000. При повреждённом словаре возможен отказ декомпрессии — это ожидаемое поведение.
21. **`sentToBot` при объединении** — логическое И. Запись, отправленная в первом словаре, но не во втором, после объединения станет `false` и будет отправлена повторно. Это осознанное консервативное поведение.
22. **Резервная папка словарей** не мигрируется автоматически. Пользователь уведомляется в UI, но должен перенести файлы вручную.
23. **Поглощение словаря с «висячими» ссылками** отменяется. Это защищает от повреждённого источника, но может помешать поглощению частично повреждённого словаря.
